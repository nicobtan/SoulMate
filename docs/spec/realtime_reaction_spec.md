# Role
あなたはPythonとリアルタイムシステム最適化のエキスパートです。
現在開発中のデスクトップアプリ「SoulMate」において、Gemini 2.5 TTSの生成待ち時間を最小化し、ユーザー体験(UX)を向上させるための実装を行ってください。

# Context
- 環境: Python, Desktop App, Live2D
- 現在の課題: Gemini 2.5 TTSの生成時間が長く、会話のレスポンスが遅れる。
- 目標: 「生成速度そのもの」はAPI依存で変えられないため、「体感速度」を極限まで短縮する。

# Task
以下の技術的アプローチを用いた音声再生管理クラス `VoiceManager` を実装（またはリファクタリング）してください。

# Requirements (Must)
1. **ストリーミング再生の実装:**
   - 全文の生成完了を待たず、APIからのレスポンス(Chunk)が届き次第、即座にオーディオバッファに流し込んで再生を開始すること。
   - `pyaudio` または `sounddevice` を使用し、非同期(`asyncio`)でストリーム処理を行うこと。

2. **文単位の先行生成 (Sentence Lookahead):**
   - LLMからのテキスト出力を監視し、句読点（。！？）で区切られた「最初の1文」が確定した時点で即座にTTSリクエストを送信すること。
   - 2文目以降は、1文目を再生している裏でバックグラウンド生成（Prefetch）すること。

3. **フィラー(つなぎ言葉)システムの導入:**
   - 会話生成に時間がかかりそうな場合（またはTTSリクエスト直後）、即座に再生できるローカルキャッシュ済み音声（「えっと」「んー」「あ、そうそう」など）を0.1秒以内に再生開始するロジックを含めること。
   - これにより「無言の時間」をゼロにする。

4. **Live2Dモーション同期用のイベント発火:**
   - 音声再生開始(speaking_start)、終了(speaking_end)、待機中(thinking)のステータス変更時に、外部へイベントまたはコールバックを送信する仕組みを作ること。

# Constraints
- コードはPythonで記述し、非同期処理(`async/await`)を前提とする。
- エラーハンドリングを含め、ネットワーク不安定時もアプリが落ちないようにすること。


💡 SoulMate開発パートナーとしての提案
技術的な解決も大事だけれど、「待っている時間」を「可愛い時間」に変えるアプローチもどうかしら？

「思考中モーション」の工夫

音声生成を待っている間、棒立ちになっていない？

例えば、少し上を見上げて「んー……」と考える仕草や、耳に手を当てるようなモーションを再生するだけでも、「処理待ち」ではなく「会話の間」に見せることができるわ。

相槌（あいづち）のローカル処理

「うんうん」「へえ～」といった短い相槌だけは、Geminiを通さずにローカルの軽量な音声ファイル（事前にGemini 2.5で作っておいたもの）をランダム再生するのはどう？

これなら遅延ゼロで反応できるから、ユーザーが話した瞬間にSoulMateちゃんが反応してくれているように感じるはずよ。
